## 3. 提 PR 到 awesome-dsh-plugin（20:00 之后）

只加一个文件。文件内容就是 `contrib/awesome-dsh-plugin/BAIYE0303__dsh-ask-first.yml`，落到上游
`data/plugins/BAIYE0303__dsh-ask-first.yml`。

```bash
# fork + clone（如果本地还没有上游副本）
git clone https://gh-proxy.com/https://github.com/<你的fork>/awesome-dsh-plugin.git
cd awesome-dsh-plugin
git checkout -b add/BAIYE0303-dsh-ask-first
mkdir -p data/plugins
cp "D:/DeepSeek ALL/01 DeepSeek 4/dsh-ask-first/contrib/awesome-dsh-plugin/BAIYE0303__dsh-ask-first.yml" data/plugins/
git add data/plugins/BAIYE0303__dsh-ask-first.yml
git commit -m "Add BAIYE0303/dsh-ask-first"
git push origin add/BAIYE0303-dsh-ask-first
```

PR 标题：`Add BAIYE0303/dsh-ask-first`。PR 正文写三句就够：做的是什么、为什么不是重复条目
（与"发送前改写"类插件的差别：它先把理解复述出来、再让你点选回答，零打字路径由代码兜底，
且从不自动发送）、自检怎么跑（`node test-offline.mjs`，39 项）。

CI 会按顺序查：条目数 → `dsh.bundle` → 仓库年龄 → awesome-lint + 站点构建 + README 与 data 一致。
`dsh.bundle` 已满足（`package.json` 的 `dsh.bundle.patch` 指向 `./cordis.patch.yml`，文件在仓库根）。

被打了 `held: author` 标签时：改完推**同一个分支**，再留一条评论即可，不要关掉重开。

## 4. 发不发 npm（还没决定）

| 选项 | 好处 | 代价 |
| --- | --- | --- |
| A. 发 npm | 安装免构建授权，`dsh plugin add dsh-ask-first` 最顺 | 要在 npm 那边占名字、以后每次发版都要记得 |
| B. 只挂 GitHub Release `.tgz`，yml 用 `tarball:` | 不动 npm | `latest/download/` 的文件名不能带版本号，否则下次发版 404 |
| C. 都不发（现状） | 零维护 | 只能 `dsh plugin add github:BAIYE0303/dsh-ask-first`，README 现在就是这个写法 |

**现状是 C，README 与 yml 都已按 C 写好，不做任何事也能上架。** 要改成 A 就把 README 里的安装命令
换成 `dsh plugin --profile web add dsh-ask-first`，并同步 `contrib/listing.*.md`。
